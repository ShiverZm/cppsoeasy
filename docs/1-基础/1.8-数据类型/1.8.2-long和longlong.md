# long 和 long long

`long` 和 `long long` 是两个类型。标准规定 `long` 至少 32 位，`long long` 至少 64 位，并且 `sizeof(long) <= sizeof(long long)`。字节数一样时，`std::is_same<long, long long>` 仍然是 `false`。

`long`、`long int`、`signed long` 是同一类型。`long long`、`long long int`、`signed long long` 是同一类型。对应的 `unsigned long`、`unsigned long long` 宽度相同，符号不同。`long long` 的范围和回绕见 [常用数据类型大小](./1.8.1-常用数据类型大小.md)。

## 各平台大小

| 数据模型 | 常见平台 | `int` | `long` | `long long` | 指针 |
| --- | --- | --- | --- | --- | --- |
| ILP32 | 32 位 Linux / Windows | 4 | 4 | 8 | 4 |
| LP64 | 64 位 Linux / macOS | 4 | 8 | 8 | 8 |
| LLP64 | 64 位 Windows | 4 | 4 | 8 | 8 |

`long` 为 4 字节时，范围是 -2147483648 到 2147483647（`LONG_MIN` / `LONG_MAX`）。`long` 为 8 字节时，范围和 `long long` 相同，都是 `-2^63` 到 `2^63 - 1`。主流平台上 `long long` 都是正好 8 字节。

Unix 选 LP64，是为了让 `long` 和指针一样宽，原来放在 `long` 里的地址继续放得下。Windows 选 LLP64，是为了让已有的 `LONG` 保持 32 位：64 位 Windows 上 `LONG` 仍是 4 字节，64 位整数是 `LONGLONG`。

## 字面量

后缀 `L` 表示至少是 `long`，`LL` 表示 `long long`。无后缀的十进制数按 `int`、`long`、`long long` 的顺序，选第一个放得下的类型。

`3000000000`（三十亿）放不进 32 位有符号整数：

| 写法 | LP64（Linux / macOS） | LLP64 / ILP32（`long` 为 4 字节） |
| --- | --- | --- |
| `3000000000` | `long` | `long long` |
| `3000000000L` | `long` | `long long`（`long` 放不下，继续升级） |
| `3000000000LL` | `long long` | `long long` |

`L` 保证的是下限。值超过 `LONG_MAX` 时，十进制字面量的类型会变成 `long long`。

## 大小相同也要分开

64 位 Linux / macOS 上两者都是 8 字节，下面几件事仍然按类型名区分。

重载和模板看的是类型名：

```cpp
void f(long);
void f(long long);

f(1L);    // f(long)
f(1LL);   // f(long long)
```

`printf` 里 `%ld` 对应 `long`，`%lld` 对应 `long long`。变参按格式符取出对应类型，两边都是 8 字节时写错仍然是未定义行为。`iostream` 按实参类型输出，没有这个问题。

整数转换等级是 `long long` 高于 `long`。同一表达式里同时出现时，`long` 会转成 `long long` 再运算。

`unsigned long` 和 `long long` 混用时，结果取决于 `long` 的宽度：

- LP64：`unsigned long` 是 64 位，`long long` 表示不了 `0` 到 `2^64 - 1` 的全部值，两边都转成 `unsigned long long`。`-1LL < 1UL` 为 `false`。
- LLP64：`unsigned long` 是 32 位，`long long` 装得下它的全部值，`unsigned long` 转成 `long long`。`-1LL < 1UL` 为 `true`。

## 和 size_t、int64_t

宽度都是 8 的时候，类型名仍然可能不同：

| 类型 | Linux（glibc，LP64） | macOS（LP64） | Windows（LLP64） |
| --- | --- | --- | --- |
| `size_t` | `unsigned long` | `unsigned long` | `unsigned long long` |
| `ptrdiff_t` | `long` | `long` | `long long` |
| `int64_t` | `long` | `long long` | `long long` |
| `uint64_t` | `unsigned long` | `unsigned long long` | `unsigned long long` |

macOS 上 `size_t` 是 `unsigned long`，`uint64_t` 是 `unsigned long long`。同时写 `void f(unsigned long)` 和 `void f(unsigned long long)` 时，传入 `size_t` 和传入 `uint64_t` 会进不同的函数。

## 移位

移位量必须小于被移位类型的位宽，否则是未定义行为。

```cpp
auto a = 1L << 32;   // long 的宽度决定这里是否有定义
auto b = 1LL << 32;  // long long 至少 64 位，结果是 2^32
```

- LP64：`long` 是 64 位，`1L << 32` 的结果是 4294967296。
- LLP64 和 ILP32：`long` 是 32 位，`1L << 32` 的移位量不小于位宽，行为没有定义。

固定要做 64 位移位时，写成 `1LL` 或 `uint64_t{1}`。

## 怎么选

- 正好 32 位用 `int32_t`。`long` 在 64 位 Unix 上是 8 字节。
- 正好 64 位用 `int64_t` 或 `long long`。`long` 在 64 位 Windows 上是 4 字节。
- 和指针一样宽的整数用 `intptr_t` / `uintptr_t`。64 位 Windows 上 `long` 比指针窄。
- 对接系统接口时沿用对方的类型：POSIX 里很多参数是 `long`，Windows API 里 32 位整数是 `LONG`，64 位整数是 `LONGLONG`。

## 自己确认

```cpp
#include <iostream>
#include <cstddef>
#include <cstdint>
#include <type_traits>

int main() {
    std::cout << sizeof(long) << ' ' << sizeof(long long) << '\n';
    std::cout << std::is_same<long, long long>::value << '\n';
    std::cout << std::is_same<std::size_t, unsigned long>::value << '\n';
    std::cout << std::is_same<std::int64_t, long>::value << '\n';
    std::cout << std::is_same<std::int64_t, long long>::value << '\n';
}
```
