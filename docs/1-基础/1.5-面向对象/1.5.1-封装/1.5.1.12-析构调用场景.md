# 析构调用场景

## 自动调用

### 栈对象：离开作用域
```cpp
void f() {
    A a;            // 构造
    {
        A b;        // 构造
    }               // b 在这里析构
}                   // a 在这里析构
```
同一作用域内，按构造的逆序析构（后构造的先析构）

### 函数返回时，局部对象与参数析构

```cpp
void g(A param) {   // param 在函数结束时析构（时机由实现定义：函数末尾或调用表达式结束）
    A local;
}                   // local 析构
```

### 临时对象：完整表达式结束时

```cpp
A make();
make();             // 临时对象在这条语句结束（分号处）析构
const A& r = make();// 例外：绑定到 const 引用/右值引用，生命周期延长到引用的作用域结束
```

### 静态存储区对象：程序结束时
```cpp
A g_a;                      // 全局对象：main 结束后析构
void f() { static A s; }    // 静态局部：第一次构造，程序退出时析构
```
按构造的逆序析构。thread_local 对象则在线程结束时析构。

### 成员对象和基类：随所属对象析构
cpp
struct B : Base {
    M m1;
    M m2;
    ~B() { }        // 先执行函数体，再析构 m2、m1，最后析构 Base
};

顺序：自己的析构函数体 → 成员（按声明逆序）→ 基类（按构造逆序），正好和构造相反。

### 容器元素：元素被移除或容器销毁时
cpp
std::vector<A> v;
v.pop_back();       // 被移除的元素析构
v.clear();          // 所有元素析构
// v 自身销毁时，剩余元素析构
// vector 扩容时，旧内存里的元素在搬迁（拷贝/移动）后也会析构

### 智能指针：引用计数归零 / 作用域结束
```cpp
{
    auto p = std::make_unique<A>();
}                   // 离开作用域，unique_ptr 析构，delete A

auto sp = std::make_shared<A>();
sp.reset();         // 引用计数归零时，A 析构
```

## 手动调用
### delete / delete[]
cpp
A* p = new A;
delete p;           // 先调用析构，再释放内存

A* arr = new A[3];
delete[] arr;       // 对每个元素析构（逆序），再释放内存

必须配对：new 对 delete，new[] 对 delete[]，混用是未定义行为

### 显式调用析构函数（配合定位 new）
cpp
alignas(A) char buf[sizeof(A)];
A* p = new (buf) A;
p->~A();            // 只析构，不释放内存（内存不是 new 出来的）

用于内存池、对象池场景，这是唯一合理的显式调用析构的场合。

## 异常
### 栈展开（Stack Unwinding）

抛出异常后，沿调用栈向上查找 catch 的过程中，所有已构造完成的局部对象都会被析构：

cpp
void f() {
    A a;
    throw std::runtime_error("err");
}                   // a 在栈展开过程中被析构

这是 RAII 能保证异常安全的基础。

注意： 栈展开期间如果析构函数又抛出异常且没有在内部捕获，会调用 std::terminate。所以析构函数默认是 noexcept（C++11 起），不要在里面抛异常。

### 构造函数抛异常

对象本身的析构不会被调用，但已经构造完成的成员和基类会被析构。

## 不会调用
|情况|说明|
|---|---|
|调用 exit()	|不会析构栈上局部对象，但会析构静态/全局对象|
|调用 abort()	|直接终止，什么都不析构|
|调用 _exit() / quick_exit()	|不析构静态对象，不执行 atexit|
|未捕获异常导致 std::terminate	|栈是否展开由实现定义，通常不展开|
|内存泄漏（new 了没 delete）	|永远不析构|
|构造函数抛异常	|该对象的析构不调用|
|定位 new 构造的对象忘了显式析构	|不析构|
|进程被信号杀死（SIGKILL 等）	|不析构|
