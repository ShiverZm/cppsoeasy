# 变量的声明和定义

声明引入名字并给出类型。定义是会为对象分配存储的声明。具有外部链接的变量，整个程序只能有一个定义。

## 概念

声明使名字在作用域内可见。定义同时确定该对象的存储；同一实体的多处声明必须类型一致。

```cpp
extern int n; // 声明：不分配存储

int n = 1;    // 定义：分配存储并初始化

struct A {
    static int s; // 类内是声明
};
int A::s = 0;     // 类外是定义
```

## 对照

### 语义

| 对比项 | 声明 | 定义 |
| --- | --- | --- |
| 存储 | 不分配对象存储，但是预定preserve | 分配存储commit|
| 次数 | 可以多次 | 外部链接：整个程序一次 |
| 违反次数限制 | 类型不一致则程序非法 | 违反单一定义规则，通常链接失败 |
| 块作用域 | 只有 `extern` 声明可以不定义 | `int x;` 本身就是定义 |

### 写法

| 对比项 | 结果 |
| --- | --- |
| `extern int n;` | 声明 |
| `int n;` | C++：定义，零初始化。C 的文件作用域：试探性定义 |
| `int n = 1;` | 定义 |
| `extern int n = 1;` | 定义。有初始化式时 `extern` 不取消定义 |
| `static int n;` | 定义，内部链接。每个翻译单元各有一份 |
| `const int n = 1;` | C++ 命名空间作用域：定义，默认内部链接 |
| `inline int n = 1;` | 定义。C++17 起多个翻译单元可以各有一份，内容必须相同 |

### C 与 C++

| 对比项 | C | C++ |
| --- | --- | --- |
| 文件作用域 / 命名空间作用域的 `int n;` | 试探性定义。同一翻译单元内重复出现会合并 | 定义。重复出现违反单一定义规则 |
| 多个翻译单元都有 `int n;` | 未定义行为 | 违反单一定义规则 |
| `const int n = 1;` 的默认链接 | 外部链接 | 内部链接。要外部链接须写 `extern const int n = 1;` |
| 试探性定义 | 有 | 无 |

### 标准版本

| 规则 | 标准 |
| --- | --- |
| `inline` 变量允许多个翻译单元给出相同定义 | C++17 |
| 类内 `inline static` 成员的声明就是定义 | C++17 |

### 编译器

只涉及 C 的试探性定义跨翻译单元时。C++ 各编译器都按单一定义规则拒绝重复定义。

| 实现 | 多个翻译单元都写 `int n;` |
| --- | --- |
| GCC 10 之前、Clang 11 之前，默认 `-fcommon` | 合并为同一个对象 |
| GCC 10 起、Clang 11 起，默认 `-fno-common` | 链接失败 |
| MSVC | 链接失败 |

## 示例

```cpp
// a.cpp
int n = 1;          // 唯一定义

// b.cpp
extern int n;       // 声明
int read() { return n; }
```

## 易错点

1. `extern int n = 1;` 是定义。只有不带初始化式的 `extern` 声明才不分配存储。
2. 块作用域的 `int x;` 是定义。要引用其他翻译单元的变量，写成 `extern int n;`。
3. 类的静态数据成员在类内只是声明。被使用时要有类外定义，或在 C++17 写成 `inline static`。
4. C++ 命名空间作用域的 `const` 对象默认内部链接，其他翻译单元看不到这份定义。
