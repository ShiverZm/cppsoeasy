# vector、set、list、deque使用场景

## vector

vector可以随机存储元素（即可以通过公式直接计算出元素地址，而不需要挨个查找），但在非尾部插入删除数据时，效率很低，适合对象简单，对象数量变化不大，随机访问频繁。除非必要，我们尽可能选择使用vector而非deque，因为deque的迭代器比vector迭代器复杂很多。

## list

list不支持随机存储，适用于对象大，对象数量变化频繁，插入和删除频繁，比如写多读少的场景。

# 对比

| 对比项 | vector | list | deque | set |
| --- | --- | --- | --- | --- |
| 底层结构 | 一段连续的动态数组 | 双向链表，节点地址不连续 | 多段连续缓冲区，由中控数组映射 | 红黑树 |
| 元素顺序 | 插入顺序 | 插入顺序 | 插入顺序 | 按键排序，键唯一 |
| 随机访问 | O(1)，下标可直接算出地址 | 只能沿节点逐个走 | O(1)，下标先定位到某一段 | 无下标，按键查找 O(log n) |
| 插入 / 删除 | 尾部均摊 O(1)；中间 O(n)，后面的元素要搬移 | 已有迭代器时 O(1)，其余节点不用搬 | 头尾 O(1)；中间 O(n) | O(log n)，插入时维持有序 |
| 内存 | 连续存放，扩容时整块重新分配并拷贝 | 每个节点多两个指针 | 多块缓冲区加中控数组，迭代器比 vector 复杂 | 每个节点有左右孩子、父节点和颜色 |
| 使用场景 | 对象简单、数量变化不大、随机访问多 | 对象大、增删频繁、写多读少 | 只在头尾两端增删 | 要按键有序保存，且不允许重复 |
