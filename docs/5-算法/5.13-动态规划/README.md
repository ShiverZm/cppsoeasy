# 动态规划的核心要素

## 一、适用 DP 的三个前提特征
特征	含义	例子
最优子结构	原问题的最优解，由子问题的最优解推出	前 i 天最大利润由前 i-1 天推出
重叠子问题	同一个子问题会被反复用到	爬楼梯里 f(3) 被算了多次
无后效性	当前状态一旦确定，未来只依赖它，与"怎么走到这"无关	dp[i] 只看 dp[i-1]、dp[i-2]，不关心之前的路径

没有重叠子问题，用分治即可；不满足无后效性，状态定义要重新设计。

## 二、DP 解题五步（写代码的要素）
### 1. 状态定义

明确 dp[i]（或 dp[i][j]）到底代表什么。这是最关键、最难的一步，定义对了后面自然顺畅。

爬楼梯：dp[i] = 爬到第 i 阶的方法数
买卖股票：dp[i] = 截止第 i 天的最大利润
### 2. 状态转移方程

当前状态如何由之前的状态推出，通常来自"最后一步有哪几种选择"。

爬楼梯：最后一步爬 1 或 2 阶 → dp[i] = dp[i-1] + dp[i-2]
杨辉三角：dp[i][j] = dp[i-1][j-1] + dp[i-1][j]
### 3. 初始化（边界条件）

递推的起点，没有它转移方程无法启动。

爬楼梯：dp[1] = 1, dp[2] = 2
杨辉三角：每行首尾为 1

初始化错误是 DP 最常见的 bug 来源，下标越界、n = 1 的特殊情况都在这一步。

### 4. 遍历顺序

必须保证计算 dp[i] 时，它依赖的状态已经算好。

依赖左边/上一行 → 从小到大遍历
一维滚动数组依赖旧值时 → 注意方向（如杨辉三角 II 要从右往左，0-1 背包一维优化也是）
### 5. 确定返回值

答案是 dp[n]、dp[n-1]，还是 max(dp[...])，要根据状态定义判断。

## 三、两种实现方式
	自顶向下（记忆化递归）	自底向上（递推）
写法	递归 + memo	循环填表
优点	贴近思考过程，只算需要的状态	无递归开销，便于空间优化
缺点	有栈深度限制	需要想清遍历顺序
## 四、常见优化：空间压缩

当 dp[i] 只依赖前几个状态时，不必保存整张表。

一维依赖前两项 → 两个变量（爬楼梯）
二维依赖上一行 → 一维数组滚动（杨辉三角 II）
## 五、以爬楼梯为例串一遍
要素	内容
状态定义	dp[i]：爬到第 i 阶的方法数
转移方程	dp[i] = dp[i-1] + dp[i-2]
初始化	dp[1]=1, dp[2]=2
遍历顺序	i 从 3 到 n
返回值	dp[n]
优化	只用 a, b 两个变量，O(1) 空间
六、做题时的思考顺序
先判断：能否拆成子问题？子问题是否重复？
想"最后一步"有几种选择 → 得到转移方程
根据转移方程反推状态需要几个维度
手算前几项验证，确定初始化
先写出正确版本，再考虑空间优化
小结

DP 的本质可以概括为：把大问题拆成有重叠的子问题，用状态记录子问题的答案，按合适顺序递推，避免重复计算。 其中状态定义和转移方程是灵魂，其余三项（初始化、顺序、返回值）是落地细节，也是最容易写错的地方。

建议的练习路线：爬楼梯 → 斐波那契 → 打家劫舍 → 最大子数组和 → 不同路径 → 买卖股票系列 → 背包问题。
